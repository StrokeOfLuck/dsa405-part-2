Start here: how the PDF becomes a CSV

The notebook starts a rebuild script. That script verifies the immutable PDFs already committed in data/raw/, copies them into data/work/, fetches only the pinned parser code, then runs the geometry parser and ticker resolver. The notebook loads those CSVs, audits them, and saves the final Part 2 CSV.

  1. Verify the raw PDF — Colab cell 3 → data/raw/2025_pdfs/ → manifest check → working copy.
  2. Find a row and read its columns — stage3_extract.py uses rectangles and embedded text. Click a field to inspect it.
  3. Build transaction fields — Stage 3 interprets dates, amounts, and assets, then writes transactions_raw.csv.
  4. Review tickers — Stage 4 writes transactions_resolved.csv, preserving earlier values.
  5. Run the notebook's checks — later Colab cells load the two CSVs and add Part 2 audit fields.
  6. Write the final CSV — p2.to_csv(...) saves the full-year table; the download here contains the selected filing.

What are we looking at?

The PDF lists transactions made by the member or a reported owner. One filing can contain many transaction rows.

What the parser needs

For each row, it must separate an asset, transaction type, trade date, and disclosed amount range. The PDF was made for people to read; copying its text is much messier.
